ducktainer может управлять несколькими хостами Docker. Добавляйте их из командной строки или в разделе **Настройки → Хосты**, переключайтесь между ними вверху боковой панели.

## Через SSH

На удалённом хосте ничего устанавливать не нужно. Нужен доступ по ключу, а удалённому пользователю должно быть разрешено использовать Docker.

```sh
sudo -u ducktainer ssh-keygen -t ed25519      # ключ в /var/lib/ducktainer/.ssh; добавьте его в authorized_keys на удалённом хосте
ducktainer endpoint add prod ssh://deploy@prod.example.com
```

Хосты SSH запоминают ключ хоста при первом подключении (`StrictHostKeyChecking=accept-new`). Изменившийся ключ отклоняется.

## Агент (исходящее подключение / Edge)

Агент подходит для узлов за NAT, файрволом или с динамическим IP: узел сам подключается к ducktainer.

1. Добавьте хост в разделе **Настройки → Хосты → Агент (исходящее подключение / Edge)** или командой ниже. Для него создаётся собственный токен.
2. На узле выполните команду из **Скопировать команду установки агента**.

```sh
ducktainer endpoint add worker-1 agent://          # выводит токен хоста
# на узле:
#   curl -fsSL -k --pinnedpubkey 'sha256//…' -H 'Authorization: Bearer <host token>' \
#     'https://<ducktainer-server>:9900/api/agent/install.sh?server=…' | sudo sh
```

- У каждого хоста-агента свой токен, действительный только для этого хоста. Административный токен агентами не принимается.
- Команда установки передаёт токен в заголовке, закрепляет сертификат этого сервера (без `--insecure`) и оставляет его на узле в `/etc/ducktainer-agent/agent.env`, доступном для чтения только root.
- Хосты, зарегистрированные более ранними версиями с административным токеном, отклоняются, пока вы не выдадите им токен в разделе «Настройки → Хосты» и не переустановите агент.

## ducktainer expose

`ducktainer expose` публикует только API Docker хоста, за списком разрешённых адресов, токеном и TLS. Запустите его на удалённом хосте: он выведет точную строку `ducktainer endpoint add …`, которую нужно выполнить на сервере.

```sh
ducktainer expose --allow <ducktainer-server-ip>
```

Добавьте `--read-only` или `--no-exec`, чтобы ограничить то, что может делать сервер. Хосты `tcp://` должны использовать TLS, если только они не находятся на той же машине. Без `--fingerprint` закрепляется сертификат, который хост предъявил при добавлении.

## Учётные данные реестров

Учётные данные для приватных реестров можно ограничить некоторыми хостами, с помощью `--hosts` или в интерфейсе. Запуски compose на узле получают копию только тех учётных данных, которые этому хосту разрешено видеть.

```sh
ducktainer registry add ghcr ghcr.io deploy --hosts prod,worker-1    # пароль через stdin
```

## Модель доверия

ducktainer управляет API Docker каждого хоста, а это равнозначно root на них. Тот, кто контролирует сервер ducktainer или его административные учётные записи, контролирует все хосты. Защищайте эту машину и `/etc/ducktainer/secret.key` так же строго, как сами хосты.

Чтобы редактировать стеки на узле, ducktainer запускает там вспомогательный контейнер (`ducktainer-files`), который монтирует `/` узла. Он завершается, если простаивает час.
