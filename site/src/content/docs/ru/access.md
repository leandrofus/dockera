## Предоставление доступа

Учётные записи — обычные системные пользователи, локальные или из LDAP/SSSD/FreeIPA. Их **роль** зависит от групп:

| Роль | Группы (по умолчанию) | Может |
|---|---|---|
| **Администратор** | `ducktainer-admins`, `docker` | всё: контейнеры, стеки, образы, терминалы, настройки, пользователи |
| **Только чтение** | `ducktainer-viewers` | видит контейнеры, стеки, образы, сети, тома и хосты; не может ничего менять, открывать терминалы, просматривать или скачивать файлы и видеть другие настройки. Пароли в строках подключения скрыты |

```sh
sudo useradd -m ana && sudo passwd ana       # только если учётной записи ещё нет
sudo usermod -aG ducktainer-admins ana       # администратор (или ducktainer-viewers: только чтение)
sudo ducktainer auth test ana                # проверяет пароль и показывает итоговую роль
```

- Членство в группах проверяется каждые 5 минут, поэтому после удаления пользователя из группы его доступ быстро отзывается.
- `root` не может войти, пока вы не включите `allow_root`.
- Всё это отображается в интерфейсе в разделе **Настройки → Доступ → Участники**: соответствие ролей группам, текущие участники каждой группы и руководство, которое напишет для вас эти команды.

## Открытие для сети

По умолчанию ducktainer слушает только локальную машину. Разрешите адреса, которые могут подключаться, и перезапустите службу. Это могут быть IP-адреса, диапазоны CIDR или имена хостов; имена хостов переразрешаются каждую минуту.

```sh
sudo ducktainer allow add 192.168.1.0/24 office.example.com
sudo systemctl restart ducktainer       # теперь слушает 0.0.0.0:9900, с TLS
```

- Все остальные отключаются до установки TLS. Локальная машина всегда разрешена.
- **Настройки → Доступ → Сеть** показывает адрес прослушивания, ваш IP и правило, которое его пропускает. Там же можно редактировать список разрешённых, и изменения применяются сразу. Также есть проверка «будет ли разрешён этот адрес?».
- Сертификат TLS самоподписанный. Его отпечаток SHA-256 выводится при запуске, чтобы клиенты могли его закрепить. Чтобы использовать свой сертификат, передайте `--cert/--key` в `/etc/ducktainer/ducktainer.env`.

## Вход

Откройте `https://<server>:9900` и войдите под своим системным пользователем и паролем.

**Аварийный токен** выполняет вход как администратор и авторизует API (`Authorization: Bearer`). Хранится только его хеш, поэтому он показывается один раз: `sudo ducktainer token --rotate` создаёт и выводит новый. Чтобы разрешить вход только системным пользователям, отключите его командой `sudo ducktainer auth set --token-login off`.
