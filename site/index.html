Manage your Docker hosts from the browser. Containers, compose stacks, images, logs and terminals, with sign-in for the Linux users you already have.

Install it

Docker must already be installed. The package sets up the service on http://127.0.0.1:9900.


      
    

    

  






  

    
What you get in the browser

    

      
Containers
A table grouped by stack or a board by state. Each container has live CPU and memory, logs, a terminal, its files, processes and settings. Editing one recreates it safely and restores the original if it fails.

      
Compose stacks
A visual editor that keeps your YAML, comments and variables intact, multi-file projects, validation before saving and combined logs. Stacks started outside dockera are found and can be edited where they live.

      
Images, networks and volumes
Pull and push with progress per layer, build from a Dockerfile, see which containers use each network and volume, and clean up what nothing uses.

      
Apps marketplace
Around 26 built-in apps plus any Portainer template list, ready to deploy as a stack you can edit.

      
Your Linux users
People sign in with their system account through PAM. Their groups decide whether they administer or only read. Removing someone from a group removes their access within minutes.

      
Audit log
Every sign-in, change and terminal session is recorded, in the UI and in the system journal.

    

  


  

    
Reach every host, without installing agents you don't need

    

      

        
SSH

        
Nothing to install on the host: dockera uses your SSH keys and the Docker CLI already there.

        dockera endpoint add prod ssh://deploy@prod
      

      

        
Outbound agent

        
For hosts behind NAT or a firewall. The host connects out to dockera with a token that only works for it.

        Settings → Hosts → Agent
      

      

        
dockera expose

        
Publishes only the Docker API of a host, behind an allowlist, a token and a pinned TLS certificate.

        dockera expose --allow 10.0.0.5
      

    

  


  

    
Built to sit next to production

    
    
      
  • Only the machine itself can connect until you allow addresses; everyone else is dropped before TLS.
    • 
      
  • Secrets in the configuration are encrypted with a key kept outside the data directory, and the access token is stored only as a hash.
    • 
      
  • The service runs as an unprivileged user; password checks go through a small root helper started on demand.
    • 
      
  • Agents, remote hosts and registries each get only the credentials they need.
